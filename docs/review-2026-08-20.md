## Context

cover the whole application rather than the operations core: the previous four
reviews concentrated on `file_ops.rs` and its neighbours, and the code they
never read — the watcher/session/load pipeline, the preview surface, the
persistence layer, the D-Bus surface, and the window layer Sprint 21 added —

The pattern from Review D holds: the quality gate was green over every defect

## The P1s, briefly

**E1 — `src/file_ops.rs`, undo of `Copy`.** `remove_merged_items` commits its
removals one at a time; when the subsequent validation of the copy's own output
failed, the outcome was `Unchanged` — the record stayed in the journal as
retryable while the merge's additions were already gone, and no retry could
ever validate again. This is the same shape as D1, one function over. Undo now
validates the output *before* removing the merge's additions, and any failure
after those removals discards the record and reports what was removed.

**E2 — the preview surface.** `open(2)` on a FIFO with no writer blocks
forever, cancellation flags cannot interrupt it, and a dropped GPUI task does
not unwind a `smol::unblock` closure — the pool thread is lost for the life of
the process. Every open on the preview surface (`preview.rs` sniff and text,
`image_preview.rs`, `thumbnails.rs`, `system_open.rs`) reached this from a
file the user merely selected — or, for grid thumbnails, merely scrolled past.
`local_fs::open_regular_file` now opens with `O_NONBLOCK` and verifies the
*opened* descriptor is a regular file, so the check cannot be raced, and every
preview open goes through it.

**E3 — `src/bookmarks.rs`.** A load error left an empty in-memory list with
nothing marking the store read-only; the next drag-in saved that list
atomically over the user's real file. The store now records why it must not be
modified — load failure, unparseable lines, or a load still in flight — and
answers every mutation with that reason instead of destroying data. Lines
Marcel cannot represent are counted rather than silently pruned, and make the
store read-only until the user fixes the file.

**E4/E5 — the load/watcher seam.** The watcher started in the `Done` arm, so a
50,000-entry enumeration was a blind window; and `apply_directory_changes` had
no `loading` guard, so an operation result landing mid-stream inserted an entry
the stream inserted again (`merge_sorted_entries` does not deduplicate). The
watcher now starts when the load starts; events and operation results arriving
while the stream owns the listing are deferred as *paths* and re-validated in
one catch-up batch at `Done`, so ordering questions collapse into "stat it
again".

**E6 — `src/window.rs`.** Sprint 21 made every launch a window and removed the
reuse that used to bound window creation; `org.freedesktop.Application.Open`
accepts 64 URIs per request from any session-bus peer, with no cross-request
limit — and the packaged FileManager1 variant is a name sandboxed applications
are routinely granted. `MAX_LIVE_WINDOWS` (32) now bounds the registry, and a
refused batch reports itself on a live window.

**E7–E10** are single-window UX correctness: reveal now scrolls to the
revealed item and navigation resets the scroll offset; `reconcile_selection`
emits a preview for a silently promoted primary; incremental Trash rows go
through `set_name` like the initial listing (sorting, filtering, and non-UTF-8
display agree with what is on screen); and bookmark menu clicks and drags
verify the bookmark's path rather than trusting an index another window may
have shifted.

## The smaller fixes (E21)

- WebP animation decode now sets the same limits as GIF (`image_preview.rs`).
- The watcher's raw-event drain is capped (`MAX_RAW_EVENTS_PER_BATCH`), so a
  churning directory cannot grow one coalescing batch without bound.
- Quarantine names near `NAME_MAX`, PDF page counts (cap 50,000, last-line
  parse), and cached page counts are all bounded against hostile input.
- A failed bookmark save re-checks for edits made during the save, exactly as
  a successful one does; each retry snapshots afresh, so it cannot loop.
- A relative `XDG_CONFIG_HOME` is ignored per the base-directory spec
  (`bookmarks.rs`, `state.rs`, `places.rs`).
- List-view Left/Right with no selection no longer jump the selection to the
  end of the folder; grid Up in the top row stays put.
- Copy/Cut only stage the clipboard, so they are no longer disabled while an
  operation runs; Paste still waits for the busy lock.
- A rename input losing focus with an invalid name cancels instead of yanking
  focus back on every click.

## Deferred, with reasons (E22)

Recorded in `TODO.md` rather than fixed here:

- **Rescan churn.** Any rescan trigger restarts the whole load, clearing
  selection and any in-progress rename, with no backoff. Preserving selection
  across watcher-triggered reloads is a design decision, not a cleanup.
- **The Trash view and Back/Forward.** `start_trash_load` never touches
  navigation history, so Back skips over Trash. Fixing it properly needs the
  virtual-location abstraction `TODO.md` already plans.
- **Folder-preview merging is quadratic on the foreground executor** and
  retains the full child listing unbounded — contrary to the AGENTS.md
  invariant. Bounding it changes what the glanceable preview shows, which is a
  product decision.
- **Thumbnail cache keys diverge from the freedesktop spec** for symlinked
  paths (Marcel hashes the canonicalized URI, the spec keys the original).
  Interop-only; no data risk.

## What this review confirms as sound

Recorded so a future review does not re-derive it: the conflict policy and its
sticky-answer scoping; `delete_ops`' identity discipline including the
hard-link ctime relaxation; archive path validation, staging, bounds, and
subprocess handling; the `--` discipline on every subprocess; stale-publication
ticket checks at every preview/thumbnail/PDF/wrap publication site; the D-Bus
URI validation core (scheme, host, bounds, type enforcement); `state.conf`
versioned atomic persistence; the drag/drop validation rules; and the fault
hook's `#[cfg(test)]` containment.

## Consequence

Nothing here reopens the operations core the previous reviews hardened — the
one exception (E1) is a corner of code Sprint 20 itself shipped. The larger
lesson repeats Review D's: the defects lived where no reviewer had read, and
the graphical acceptance matrix remains unrun and remains the gate between
this tree and a release-readiness decision. Two of this review's fixes (E7,
the reveal scroll, and E17, cold-activation launch) also need that graphical
session to be confirmed by eye.
