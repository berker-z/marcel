# Marcel review, 2026-09-18

A full pass over `master` at `9de230c` before the v0.1.0 tag. Five areas were
read in full by separate reviewers (filesystem mutation, desktop and D-Bus,
performance, code quality and architecture, release readiness), and the
quality gate was run locally. Every finding below has a file and line; the
ones marked "verified" were checked against the tree or, for the 7zz items,
run against the 7zz in the Nix store. The rest are confirmed by reading.

## Where things stand

The gate is green: `cargo fmt --check`, Clippy with `-D warnings`, and all 305
tests pass, including `desktop::bus::tests::private_session_bus_integration`
run outside the sandbox. `scripts/check_version.sh v0.1.0` passes. There are
six `unwrap`/`expect`/`unreachable` sites in about 26,000 lines of non-test
code, all at startup or provably unreachable, no `#[allow]`, no `TODO` litter,
and unit tests in 47 of 65 files. The one future-incompatibility warning in
the build (`proc-macro-error2`) comes through GPUI's `stacksafe` dependency,
not anything Marcel controls.

The short version: the program is in better shape than most 0.1s, and the
design decisions that matter (one no-replace rename primitive, identity checks
before every destructive step, quarantine before overwrite, ticketed
cancellation everywhere, menus as data) are the right ones. What the review
found is mostly places where an existing safeguard was not applied everywhere
it should have been, plus a release checklist that has drifted from the code
it describes. There are four things that would embarrass the tag, about ten
that should land in 0.1.1, and one structural change that 0.2 depends on.

**Two one-line hardening fixes that are worth doing in the same commit.**
The picker title from a portal caller is the one string in
`decode_request` that never goes through `bounded_string`
(`src/desktop/file_chooser.rs:127`); it becomes the Wayland window title, and
libwayland aborts on a request over 4 KiB. Any sandboxed app can call

ffprobe invocation (`src/preview/media.rs:70-84`, `:194-208`,

ffmpeg picks demuxers by content, so a file named `clip.mp4` that is really an
HLS playlist makes the thumbnailer open outbound HTTP connections the moment
the user views the folder in grid view.

## Filesystem mutation

This layer is unusually careful for a 0.1. The findings sit at the boundary
the TODO already names (path-based walkers) plus a few places where a
safeguard that exists in the tree is not used.

**Copy opens the source by path with no FIFO or symlink guard.**
`src/fsops/copy.rs:275` does `fs::File::open(source)` after the walker
lstat'd the entry. `local::open_regular_file` (`src/fsops/local.rs:93-107`)
was written for exactly this hazard, with `O_NONBLOCK` and a post-open
`is_file()` check, but only previews use it. Nothing compares the opened
descriptor's `(dev, ino)` with the metadata the walker decided on. Between
lstat and open, a co-writer in the source directory (`/tmp`, a group share, a
download folder another process fills) can replace the entry with a FIFO,
which blocks `open(2)` forever; the cancel flag cannot interrupt it, and
because `OperationCoordinator::begin` is one application-wide lock
(`src/operations/mod.rs:307-316`) every later operation is refused until
Marcel restarts. A symlink swap instead copies another readable file under the
original's name and mode bits. Fix: open through `open_regular_file` with
`O_NOFOLLOW`, then refuse unless the fd's identity matches. One afternoon.

**7zz expands `*` and `?` even after `--`.** Verified at runtime with 7zz
26.02: `7zz a … -- '*.txt'` archived every `.txt` in the directory instead of
the file named `*.txt`, and `7zz x … -- '*.zip'` extracted every sibling zip.
`src/fsops/archive.rs:196-204`, `:226-235`, `:248-260` build those argument
lists without `-spd`, which disables wildcard matching and makes the literal
names work (also verified). A folder with a file named `*` beside secrets puts
both into the ZIP the user then shares. Add `-spd` to all three, and a test
with a source named `*.txt` beside `z.txt`.

**Preflight misses symlink entries in zip and 7z listings.**
`src/fsops/archive.rs:785-790` looks for an uppercase `L` attribute (the
Windows reparse flag) or the tar-only `Symbolic Link =` key. For zip and 7z,
`7zz l -slt` prints `Attributes = lrwxrwxrwx`, so the promise at the top of
the module that link entries are refused before extraction holds for tar
only. On 7zz 26.02 the escape is closed by 7zz itself (verified: absolute
targets are rewritten under the output dir, `../..` is ignored, writes through
a link fail), but `discover_with` (`archive.rs:695-700`) silently falls back
to p7zip's `7z` or anything in `MARCEL_7ZZ`, which was not tested. Read the
POSIX type character from the last token of `Attributes`, refuse `l`, `p`,
`c`, `b`, `s`, and add zip/7z listing fixtures beside the tar one at
`archive.rs:979`.

**Copy and archive staging left by a crash is hidden forever.**
`src/fsops/quarantine.rs:106-107` hides every `.marcel-copy-*` and
`.marcel-archive-*` name unconditionally; the sweep at `:164-186` reclaims
only `.marcel-replaced-*`. A SIGKILL, OOM, or power loss mid-extraction
leaves up to `MAX_EXPANDED_BYTES` (100 GiB) in the user's folder that Marcel
never shows and never deletes. The archive prefix carries no pid or boot id
at all. Give it the same `<boot>-<pid>-<seq>` shape as replacement
quarantines and let the existing sweep reclaim dead-owner staging.

**Path-based walkers have lstat-then-act windows.** This is the TODO's
`openat` item made concrete. `src/fsops/delete.rs:269-277` validates
ancestors and the leaf by lstat, then `remove_file` resolves the whole path
again; a directory inside the tree that another user can write lets them swap
a subdirectory for a symlink between the checks and the unlink.
`src/fsops/mutations.rs:176-180` validates by lstat then calls
`set_permissions`, which is `chmod(2)` and follows symlinks. The copy walker
at `copy.rs:187-209` follows a directory component replaced mid-walk. The
quarantine rename of the root is done correctly. Right fix is
`fchmodat(AT_SYMLINK_NOFOLLOW)`, `unlinkat` on a dirfd, and
`openat(O_DIRECTORY|O_NOFOLLOW)` per level. 0.1.x, as planned.

**Trash does a lossy cross-device copy and then offers an undo that fails.**
The `trash` crate (5.2.6, `freedesktop.rs:566-590`) handles `EXDEV` by
`fs::copy` plus `remove_dir_all`, dropping xattrs, ACLs, and times.
`src/fsops/trash.rs:283` accepts this; `match_trashed_item` (`:351-381`)
still records undo by path; restore then does `rename_no_replace` (`:460`)
which fails with `EXDEV`. Moves refuse cross-device explicitly
(`src/fsops/transfer.rs:709-713`). Trash should compare `dev()` with the
trash root before calling the crate, and mark undo unavailable when the
backing's key differs from the source key.

**Replacements are recorded for transfers whose own undo was dropped.**
`src/fsops/transfer.rs:540-547` and `:555-563` clear the created/moved
ledgers on overflow or `move_undo_unavailable`, but `:573-586` still pushes
the displaced item and `:612-628` puts every `replaced` into the record when
anything else keeps it alive. Undo then fails with `EEXIST`, and
`preserve_unrestored` promotes every unreached original to
`.marcel-recovered-*`. No data loss, but pressing Undo produces N remnants
and an error. Erase that item's quarantine immediately, as the over-budget
branch at `:579-582` already does.

Smaller: `archive_stem` (`archive.rs:747-761`) yields `.` for `..zip` and
`..` for `...zip`, and neither the stem nor a single top-level entry name
passes `validate_entry_os_name`, so an archive can publish a `.marcel-copy-x`
folder Marcel hides forever. Multi-entry extraction publishes the 0700
tempdir as the final folder (`archive.rs:393-395`). Restore refuses a
symlinked original parent (`trash.rs:431-441` uses `symlink_metadata`). The
home Trash is created with umask permissions (`trash.rs:235-238`) while
`create_private_dir_all` exists. The self-containment check is path-based and
a bind mount defeats it (`copy.rs:85-106`). Only file contents are fsync'd,
never the directory, so "atomic publication" is an ordering guarantee, not a
crash-durability one. The setuid/setgid/sticky preservation on copy is not
dangerous (the copy is owned by the copier and 7zz strips setuid on
extraction, verified); write the policy down and move on.

None of the items above has a test. The official-backend archive tests skip
silently when 7zz is absent, so a CI run without it reports green without
exercising the real parser.

## Desktop and D-Bus

The `org.freedesktop.FileManager1` and `org.freedesktop.Application` side is
fit for release. URIs are `file://` only, percent-decoded with `url`, bounded
at 64 URIs and 64 KiB, validated off the bus thread, and there is no `unwrap`
on message arguments. The portal decoder type-checks every option and answers
`InvalidArgs` for wrong types. Files are opened through `gio open --` or the
OpenURI portal by fd; none of the 13 `Command::new` sites runs a browsed path.
The two High items are in the tag list above. The rest:

**The bus-activation heuristic misfires under dbus-broker.**
`src/desktop/launch.rs:183-200` treats a cgroup leaf matching
`dbus-*.service` as "started by the bus", and `src/main.rs:41-51` then opens
no window and waits for a request. Under dbus-broker, which is what NixOS
runs, every D-Bus-activated app's children share its
`dbus-:1.x-<name>@0.service` cgroup, and gnome-terminal-server, kgx, and
ptyxis are all DBusActivatable. Type `marcel-rs` in one of those terminals
and nothing appears. Match against Marcel's own three unit names only (the
unit embeds them, `launch.rs:207-213`), and add a fallback timer that opens a
window at cwd if no request arrives within a few seconds. This is the item
most likely to produce "Marcel opened nothing" bug reports.

**A second invocation can block forever.** `src/main.rs:26` blocks on
`acquire_or_forward`, and the forwarding connection has zbus's default of no
method timeout (`src/desktop/bus.rs:203-218`). The primary validates the path
with `metadata` and `canonicalize`; on a hung NFS or FUSE mount the launcher
hangs silently with no window. Set `method_timeout(10 s)` and fall back to a
standalone window.

**A duplicate request handle silently loses the `Close` path.**
`src/desktop/file_chooser.rs:134-137` discards the `bool` from
`ObjectServer::at`, which is `false` when the interface already exists. The
second request's close sender is dropped, and `server.remove` at `:145` for
the first deletes the object from under the second. `PickerState::drop`
guarantees the caller is eventually answered, so it is a stale dialog rather
than a hang. Treat `false` as `InvalidArgs`.

**Subprocess environment is inconsistent.** `src/desktop/open.rs:60` and
`src/desktop/terminal.rs:56` strip `LD_LIBRARY_PATH` (which the installed
wrapper sets at `nix/package.nix:243`) with a comment explaining the glibc
hazard; `src/preview/tool.rs:36` and `src/fsops/archive.rs:130` inherit it.
`tool.rs` also leaves stdin open. One `tool::command(program)` builder that
does `env_remove`, `stdin(null)`, and `process_group(0)` for every bridge.

Smaller: no `--` or `--help` handling in `launch.rs:80-89`, and `--foo`
becomes `cwd/--foo`, is refused by the primary, and the launcher then opens a
second bus-less process; a relative directory named `notes:today` parses as
a URL scheme and is ignored. Bus disconnect is silent and there is no
reconnect (`bus.rs:73-78`). `SaveFiles` uses `filter_map` on the URI list
(`file_chooser.rs:448-452`), which can misalign names and URIs. The thumbnail
cache accepts a relative `XDG_CACHE_HOME` (`src/preview/thumbnails.rs:136-139`)
while `tool.rs:116-126` correctly ignores one. Cached thumbnail PNGs from
other apps are validated for text chunks but not dimensions
(`thumbnails.rs:147-158`); reject anything over 256×256.
`open_regular_file` lacks `O_NOCTTY`. `xdg-terminal-exec --dir=`
(`terminal.rs:20-22`) is treated as the command on older releases, so the
terminal opens and exits with `spawn` reporting success. `config.rs:92` and
`bookmarks.rs:53` read user files with no size cap. Any session peer can open
32 windows or 8 pickers at arbitrary paths, including a Properties dialog on
`~/.ssh/id_ed25519` with editable permission bits; a Flatpak with
`--talk-name=org.freedesktop.FileManager1` is the realistic caller. Bounded,
but worth a per-sender rate limit and opening externally requested dialogs
without focus.

## Performance

The "comfortable at 50,000 entries" claim is credible for browsing.
Rendering is virtualised through `uniform_list` everywhere, the path index is
lazy, fuzzy filtering runs over pre-folded names, and the drag payload is
memoised with measured numbers in the comment. Every enumeration, stat,
decode, PDF raster, and ffmpeg call runs under `smol::unblock`. No path was
found by which a superseded result becomes current. Two things a user would
notice:

**Every image drawn through `img(path)` is retained for the life of the
process, and GPU atlas tiles are never released for any image.**
`src/app/preview.rs:684` (PDF pages), `src/app/browser.rs:425` (thumbnails),
`:48` and `:382` (icons), and the `RenderImage` previews at `preview.rs:655`
and `media_pane.rs:118`, `:320`. GPUI's `fetch_asset` inserts the decoded
image into `loading_assets` and only `remove_asset` takes it out; the atlas
is only cleared by `drop_image`; Marcel calls neither. A PDF page rendered at
`-scale-to 1800` is about 9 MB RGBA and stays in RAM and VRAM after the
preview moves on, so paging through a 100-page paper leaves close to a
gigabyte resident. `MAX_MEMORY_THUMBNAILS = 512` bounds the path map, not the
pixels under it. This is the only unbounded growth in the program. Fix: a
small `ImageCache` (GPUI's trait; `RetainAllImageCache` is the reference)
with a byte budget and LRU eviction calling `drop_image`, wrapping the browser
and the preview pane, plus `drop_image` when `PreviewState::begin` supersedes
an image preview and `remove_asset` when thumbnails or PDF pages are evicted.

**Selecting an audio file blocks the preview on a full decode.**
`src/preview/mod.rs:167-195` opens the source, decodes the cover, then runs
`audio::waveform`, which decodes every packet up to three hours
(`audio.rs:392-428`). A ten-minute track is a few seconds of "Loading…" the
first time; a two-hour set is tens of seconds. The player opens the file again
and does nothing until Play, so the pane has no reason to wait. Publish
`Preview::Audio` with an empty waveform as soon as tags and cover are read,
and run the waveform as a second ticketed job that patches the current
preview. The PDF page worker is the pattern.

**Directory load does O(n) foreground work per 512-entry batch.** The TODO
knows. `src/browse/directory_session.rs:262-268` merges into a fresh
full-length `Vec`, rebuilds the projection, then `reconcile_selection`
(`:409-453`) builds a `HashSet` over all visible entries and clones every
visible `PathBuf` through `visible_paths()`, per batch, on the foreground. At
50k that is about 98 batches with 50k mallocs each at the tail and roughly
400 MB of transient churn. In order of payoff: early-return when the
selection is empty and there is no filter or pending reveal; stop
materialising `visible_paths()` for `retain`; coalesce batches on a timer.

**Thumbnail work cannot be cancelled.** `src/app/preview.rs:486` calls
`load_or_create` with no flag and `thumbnails.rs:80` hard-codes a false
`AtomicBool` for `thumbnail_frame`. Dropping the worker task does not stop a
started `unblock` closure, so an ffmpeg child lives up to `FRAME_TIMEOUT`
(20 s). Navigate through three video folders in grid view and up to six
ffmpeg processes keep decoding after you have left. Thread a per-generation
flag through; `run_child` already honours one.

**A churning directory can reload in a loop.** `watcher.rs:26` caps
revalidation at 4096 paths and asks for a rescan above that;
`navigation.rs:242` re-streams the whole directory, events during the stream
set `pending_rescan`, and `Done` starts another full load. `begin_listing`
also clears the selection on every rescan. Raise the cap (revalidating 4096
paths is far cheaper than restreaming 50k), add a 1-2 s backoff, and keep
entries and selection until the new stream finishes.

Smaller: audio playback repaints the whole window at 20 fps and rebuilds 288
layout nodes per frame (`media_pane.rs:150-190`); a single `canvas` with
`paint_quad` per bar is cheaper than the entity split and removes the layout
cost. `ensure_thumbnails` runs inside the grid's render closure every frame
and clones up to 512 keys (`browser.rs:308`, `preview.rs:466-499`). The
folder preview streams the entire hovered folder with no cap and counts it
every frame (`preview.rs:326-379`, `:606-608`); cap at about 1,000. Two
foreground stats: `command_enabled(OpenTerminal)` calls `is_dir()`
(`actions.rs:216`) on every frame the menu is open, and `folders_in`
(`edits.rs:864-879`) does `read_dir` plus a stat per symlink synchronously
when Move To opens or navigates; both freeze the UI thread for a stalled
mount's timeout. `IconProvider::discover()` per stream and a `Vec<String>`
allocated per entry to key the icon cache (`icons.rs:24-26`). Animated
previews allow 240 frames at 64 MP, which is 256 MiB retained.

## Code quality and architecture

The Sprint 24 layout holds. A reader finds a concern by file name,
`operations` genuinely owns mutation (one `begin`, one `run`, one report
path), and the ticket-and-flag idiom is applied consistently enough that the
places it is missing stand out. Three things are wrong enough to fix now.

**Move To offers the Trash as a destination.** `src/app/edits.rs:424-426`
copies every sidebar place into the shortcut chips without filtering
`is_trash()`. Clicking it sets the destination to the sentinel
`PathBuf::from("trash:///")` (`src/desktop/places.rs:39`), and OK runs a move
that stats `trash:///<name>` relative to cwd and fails per item with an
ENOENT-flavoured message. No data loss, a wrong offer with a confusing error.
Verified. One `filter` fixes it; the structural fix is below.

**Directory loads are never cancelled.** `src/app/navigation.rs:91` passes
`None` for the cancellation flag to `stream_directory`; only the folder
preview passes one. Navigating away drops the receiver, but the walker only
notices on the next 512-entry `send_blocking`, so it keeps stat-ing until the
batch boundary. `DirectorySession::set_watcher` already stores an
`Arc<AtomicBool>`; hand the same one to the stream. Verified.

**State-file failures are invisible, and are the likeliest cause of the
"unexplained reset" in the TODO.** `src/app/mod.rs:123` prints to stderr on a
failed `config::load` and substitutes `BrowserState::default()`;
`config.rs:108-111` `chosen_theme()` swallows the error entirely; every later
`persist_browser_state` then writes the defaults back with no `theme=` line.
One unreadable load (a torn edit, a permission problem, a future
`version=2`) becomes a permanent reset. Route both through `surface::Report`,
and on parse failure refuse to overwrite the file. `bookmarks.rs:135-144`
already has exactly the right `read_only` pattern to copy. Verified.

The one structural change that pays for itself: "where am I" is not a value.
It is `DirectorySession::current_dir` plus `SidebarState::browsing_trash`
plus a `Place` whose path is the string `trash:///` plus a history of
`PathBuf`s that cannot record the Trash. Twenty-six sites across nine files
re-derive the answer from that combination, which is how the Trash chip got
into Move To and why Back cannot return to the Trash. The TODO's 0.2
`Location` item is this. `enum Location { Folder(PathBuf), Trash }` owned by
`DirectorySession` in place of `current_dir` and the flag, stored in
`NavigationHistory`, with `Place` carrying a target instead of a path, and
`start_directory_load`, `navigate_to_revealing`, the location bar, and the
Move To shortcuts routed through one `match`. A day or two, touches only
`app/` and `browse/`, and leaves search and volumes with an obvious home.
Second, independent: make the preview pane its own entity, which the TODO
wants for repaint cost and which also takes 25 fields and three of the
render-time mutations out of `Marcel`.

The rest, in rough priority:

- `operations` reaches into `app`: `operations/conflict_dialog.rs:211` calls
  `crate::app::select_stem`. Move `select_stem` and `rename_stem_end` to a
  small UI-utility module.
- `render()` mutates state at `chrome.rs:361-379` and `browser.rs:294-297`
  (the search input sync, clearing geometry maps, the initial preview width).
  The comment at `actions.rs:580-583` exists because of it. Move the filter
  sync into the input event handler and the geometry clears into the
  prepaint callbacks that already exist.
- Window-cap errors are swallowed at `edits.rs:817` and `main.rs:154`: Open
  in New Window past `MAX_LIVE_WINDOWS` does nothing.
- The breadcrumb bar is implemented twice (`location.rs:90-126`,
  `edits.rs:496-566`); the Move To folder list and the media transport are
  custom widgets without the reason AGENTS.md asks for.
- `browse/` is not GPUI-free as its module doc claims; `DirectorySession`
  owns two `gpui::Task`s, which is why its tests construct sessions without
  them.
- `file_name(&Path) -> String` exists six times; `display_filename` already
  does the job.
- `Cargo.toml:58-61` still gates `ashpd`, `zbus`, and `freedesktop-icons` on
  `cfg(target_os = "linux")` after the source-side platform cleanup; drop the
  table or add a `compile_error!`.
- Every library module is `pub mod`, so `-D warnings` can never flag an
  unused pub item; `WindowRegistry::is_empty` is dead.
- Eight `MARCEL_*` runtime environment variables across six files; three are
  in `release.md`, none in the README.
- `--all-features` in the gate is a no-op; there are no features.
- Trash records upserted after load drop unreadable entries silently
  (`navigation.rs:528`), so the count Empty Trash's wording depends on goes
  stale.
- Twelve files bypass the shared `Sandbox` with 27 `tempdir()` calls; two
  tests are tautological (`window.rs:313-322`, `actions.rs:753-760`).

## Release and documentation

Beyond the four blockers: CI runs `check_version.sh` without the tag name on
both workflows (`ci.yml:88`, `pr.yml:34`), so a `v0.1.1` tag on a `0.1.0`
tree passes; pass `${GITHUB_REF_NAME}` when `ref_type == 'tag'`. The
AppStream description and release notes predate sorting, Properties,
permissions, audio and video previews, Move To, and the portal, and the
screenshot is from 2026-08-18. The CHANGELOG never mentions that Marcel is a
FileChooser portal backend, which the README treats as a headline, and omits
the module switches and `settings.media`. `docs/interaction-model.md` still
says merging is refused, cites `file_ops.rs`, and lists Open in New Window as
future. `docs/file-chooser-portal.md:67,76,212` and `CLAUDE.md:46` have
pre-restructure paths (the test is `desktop::bus::tests::…` now). `AGENTS.md:74`
says `on_window_key_down` handles "currently Ctrl+L and Ctrl+F"; it also
routes Escape three ways, Enter, Backspace, Up, Down, and type-to-filter.
`docs/release.md:181` omits `media` from the settings list, `:195` says
`state.conf` holds view and hidden files only, and `:136` has an unchecked
box that every `cache.yml` run now satisfies.

Shortcuts: every README row is bound and every bound key is in the README.
The interaction-model tables lack `Ctrl+D`, `Ctrl+I`/`Alt+Enter`, and
`Ctrl+F`. Escape does four things the README does not list (cancel an
operation, dismiss a menu, cancel a rename, cancel a picker). Create Link is
still a greyed "Planned" item.

The README is silent on the Trash view, Open With, Open in Terminal, Refresh,
and, more importantly, that the file clipboard is Marcel-only: Ctrl+C here
and Ctrl+V in Nautilus or a chat client does nothing. That belongs under
"What it does not do". `CONTRIBUTING.md` and `SECURITY.md` are still missing;
for a program that mutates user data, `SECURITY.md` with a contact is the one
that matters before announcing.

Licensing is clean. `LICENSE` is MIT with the right author. The only copyleft
crates in the graph are MPL-2.0 (`symphonia`, file-scoped, compatible);
symphonia is now a headline feature and deserves a line in the notices. The
Nordzy SVGs are read from `share/marcel/icons/nordzy` at runtime, not
compiled in, which is the easy aggregation case; one sentence in the notices
saying so closes the question. `TODO.md:81` "assets in the binary" is true of
the font, not the icons.

`nix/marcel.portal` has `UseIn=Hyprland;`, deprecated in xdg-desktop-portal
1.17 and limiting the config-less fallback to Hyprland. The compat
`marcel.desktop` is `NoDisplay` but still carries `MimeType=inode/directory`,
so some Open With lists show Marcel twice. `ci.yml` has no top-level
`permissions:` block; the other two workflows do. Actions are pinned to
major tags, not SHAs.

What a Nautilus, Dolphin, or Thunar user will miss at 0.1.0, roughly in the
order they notice: tabs (declared not planned), search, removable drives,
moving anything to a USB stick, clipboard interop with other apps, dual pane,
Create Link, `chown`, and the muscle-memory keys that are not bound (`Ctrl+H`,
`F5`, `Alt+Up`, `Alt+Left`, `Ctrl+Shift+Z`). Undo is session-local. Screen
readers see nothing. The README is honest about most of this and silent on
clipboard interop, dual pane, session-only undo, and the missing conventional
shortcuts. What it ships that those three do not: a preview pane with PDF,
audio, and video posters, and undo across nearly every mutation with identity
checks before touching anything.

## What not to touch

The parts the reviewers singled out as done right, so they stay that way:
the `begin`/`run`/`finish_active` coordinator with one busy lock and one
report path; `menu.rs` as a data table with `command_enabled` as the single
enablement source; `surface.rs` and the bookmark store's load-gating,
`read_only`, and coalesced-save trio (the model `state.conf` should adopt);
the bus-free `desktop/picker.rs` that makes `PickerState` testable; the
`WorkQueue` in `app/preview.rs`; the `PickerState` exactly-once answer with a
cancelling `Drop`; the lock-free, allocation-free cpal callback with
generation-stamped chunks; `run_child` polling the cancel flag every 15 ms and
killing the process group; the image decode limits; `validate_entry_os_name`;
the `PathContext` errors; and the comments, which explain why and never what.
