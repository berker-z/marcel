Scope: everything since the Sprint 28 review closed (`b3796d1..44c4f2f`, about
8,100 added lines: Sprints 29–31, the desktop clipboard, HEIF/AVIF, the
sidebar fold), plus the uncommitted home-Trash-only change. Five read-only

Gate: `cargo fmt --check`, clippy `-D warnings`, 449 tests green, plus both

## Verdict

The individual pieces are good. Every sprint has a document with decisions
and acceptance checks, the error wording and comment voice match `fsops`, no
D-Bus call blocks the UI thread, and the cross-device move is careful where
it matters most: fsync before removal, quarantine by rename, `RENAME_NOREPLACE`
on undo.

What went wrong is ordering. The 0.2 plan
([`sprints/0xx-every-place-a-file-lives.md`](sprints/0xx-every-place-a-file-lives.md))
put `Location` first, alone, so that every later place would be a variant the
compiler checks. Sprints 29 and 30 deferred it on purpose, and drives, shares,
and remoteness went in as three more ways of asking "where am I" from a
`PathBuf`. The uncommitted Trash change is the first fix that had to remove a
feature for want of that type. More of those follow if search or per-drive
Trash is built on the current shape.

## 1. Structure

**`Location` was not built.** `browsing_trash` is read at 28 sites in nine
files (27 when the plan was written). `trash:///` and `PlaceKind` remain
(`desktop/places.rs:26-45`). History stores `PathBuf` (`browse/history.rs:8`),
so Back from the Trash skips the folder that was open before it.
`start_trash_load` still duplicates `start_directory_load`
(`app/navigation.rs:98/220`).

**The kind of place is re-derived in three parallel ways:**

- `VolumeStore::volume_containing` (`volumes.rs:132`), used at sidebar.rs:343,
  :365 and location.rs:224.
- `NetworkStore::mount_containing` (`network/mod.rs:307`), used at
  location.rs:219, network.rs:69 and :357; `active_server` at network.rs:200
  does its own `starts_with`.
- `remoteness::of` (`browse/remoteness.rs:66`), read at preview.rs:488, :702
  and properties.rs:669.

Only `mounted_breadcrumbs` (location.rs:213) decides which of them wins.

**The mount table is parsed three times** (`remoteness.rs`, `TrashSites` in
`fsops/trash.rs:560`, UDisks `MountPoints`). Octal unescaping is written four
times, and `trim_nul` twice (`gvfs.rs:141`, `desktop/volumes.rs:581`).

**`app/` holds GVfs types.** `NetworkTarget` carries `gvfs::{Location,
MountSpec}` (`app/state.rs:21,263`). `app/network.rs` builds a `gvfs::Location`
by hand. `is_network_uri` (location.rs:50) is a second scheme check beside
`Location::parse`, and the two can disagree. `gvfs::Location` also takes the
name the plan reserved for the enum.

**Bolted-on filters:**

- The uncommitted Trash change filters `trash::os_limited::list()` down to
  the home Trash (trash.rs:146). The crate still walks every mount's Trash
  first, so a stalled NFS mount can still hang the listing. Items trashed on
  a stick become unreachable once Undo is gone. This also invalidates Sprint
  29's ticked check at `029:167`.
- Move To still filters out the Trash with `is_trash()` (edits.rs:776-786),
  and it offers no drives or shares, which are the case people want it for.
- Picker exclusion of the Trash sits in two places (sidebar.rs:540 and
  picker.rs:153); AGENTS.md asks for one.
- Four `Option<…Menu>` fields clear each other by hand (sidebar.rs:~392,
  navigation.rs:71).

### Sprint 33: Location (the plan's part one, extended)

One reviewable change, compiler as the checklist.

- `enum Location { Folder(PathBuf), Trash(TrashScope) }`, owned by
  `DirectorySession`. History stores it, `Place` targets it, and
  `start_load(Location, LoadKind)` replaces the two loaders.
- One `mounts.rs`: a mount-table snapshot with a deepest-match lookup.
  `remoteness`, `TrashSites` and both stores read it. It also holds the one
  unescape and the one `trim_nul`.
- A `PlaceInfo { mount: Option<MountRoot { kind: Drive | Share, label, root }>,
  locality }`, resolved once when the directory changes. Crumbs, sidebar
  highlight, `leave_*` and preview gating read it instead of asking three
  stores.
- `TrashRecord` carries its Trash root. `Location::Trash` shows home by
  default and a drive's Trash while that drive is browsed. Empty acts per
  root and reports a read-only Trash without failing the rest. The listing
  asks only the roots it needs, which removes the stalled-NFS path.
- Around it:
  - Move To offers drives and shares and drops its `is_trash()` filter.
  - The picker refuses the Trash in one place.
  - `SidebarMenu` becomes one enum.
  - `gvfs::Location` is renamed `ShareAddress` and stays out of `app/`
    behind a `ShareId`.
  - `is_network_uri` goes.

## 5. Working rules going forward

These are not new rules; AGENTS.md and the sprint docs already imply them.
They are written down because the last two weeks drifted from them.

1. **A sprint doc before the code**, including for "small" features (the
   clipboard, HEIF) and for follow-up fixes. A fix that needs a second fix
   goes back into the doc as a check.
2. **The plan's order holds unless the doc is changed first.** Deferring
   `Location` was a reasonable call, but it was made inside two sprint docs
   and never written back into the plan it deviated from.
3. **One sprint, one commit or a few.** Split by layer where it helps (fsops,
   then the desktop service, then the UI). Nothing sits uncommitted across
   sprints.
4. **A new kind of place is a type, not a `starts_with`.** After Sprint 33,
   code under `app/` that inspects a path to learn what kind of place it is
   is a review finding.
5. **Every destructive path has a test at each failure point** before its
   sprint is closed. Sprint 29's tests covered the happy path and the FAT
   metadata drop, but not the failures after a copy is published.
6. **Update the module map and the TODO pointer in the same change** that
   adds a module or a sprint.
7. **`{error:#}`** wherever an anyhow error reaches a user.
